## What was built
- Generic engine additions (no class names; AC-4 grep is clean), tests in `tests/test_engine_segments.py`
  (a YAML-only fake class "deklaracja_klubu" on synthetic word-box and plain-text documents):
  - `segments` strategy (`odw2json/engine/strategies.py`): splits every line in scope into column segments
    (word-box gap > the `after_label` column gap; plain text: 2+ spaces) and yields every match of `value` in a
    segment. Filters: `exclude` (segment, leading dots removed, starts with one of these regexes), `not_after`
    (regex ending right before the value, e.g. a title "adw."), `raw: true` (match `value` case-sensitively on
    the original text, used for capitalised person names). Regexes compiled at load (`_check_regexes`).
  - `list_of_blocks.min_blocks`: fewer block starts than this -> one item over the whole scope (default off, so
    existing recipes behave as before).
  - `list_of_blocks.merge`: the blocks are merged index-wise into the list already at that path (extra blocks
    join the last item). Used to attach signature groups to the principals found earlier.
  - `recipes/recipe.schema.json` documents all of the above.
- `recipes/pelnomocnictwo.yaml`:
  - `mocodawca` is a list of blocks: consortium members enumerated inline or per line
    ("(Konsorcjum): 1) X sp. z o.o., ..., KRS ...; 2) Y sp.j., ..."), leader/partner phrasing, "Wykonawca 1";
    with fewer than 2 starts the whole document is one principal.
  - `data.nazwa`: "Mocodawcą jest", "w imieniu / do reprezentacji X (" (not "Wykonawcy"), "pod firmą X",
    label "Mocodawca" right or below (grid and two-column header layouts), enumerated party, name with a legal
    form at a line start ("X sp. z o.o., ul. ..."). Names wrapped across lines are joined.
  - `data.imie_nazwisko` + `typ`: sole traders ("Ja, niżej podpisany X, prowadzący działalność ...") ->
    `osoba_fizyczna`; KRS or a company name -> `osoba_prawna`.
  - `podpisujacy`: `segments` over the signature section (from the first dotted line, including a
    "W imieniu X:" / "Za X" caption above it); role lines, stamps, "Za X" and attorneys ("adw.", "r. pr.") are
    excluded; groups "W imieniu X:" are merged into the principals in order.
- `recipes/przelew.yaml`: account number wrapped across lines in the letter layout ("na rachunek nr ..."),
  label "Nr ref. operacji:", transaction id must contain a digit (was taking the word "operacji").

## Held-out independence: NOT fully independent (owner's decision)
Cases 01-40 contain no consortium and no sole trader; my generic attempt from real-world conventions left
pelnomocnictwo at 0.81. With the owner's explicit OK (chat, 2026-11-21) I looked at the text layout of held-out
cases 41, 44, 48 and at pred-vs-gold diffs of `nazwa`/`podpisujacy` in 41-60, then wrote generic rules for the two
layouts found there (inline enumerated consortium members; "W imieniu X:" signature groups; "pod firmą X" wrapped
across lines). No gold value was copied. The pelnomocnictwo held-out number (0.9971) is therefore optimistic: treat
it as a dev number. A new untouched set (e.g. the noisy T010 cases or hidden test) is the honest check.

## Decisions
- Signatories are person-name shaped segments (two capitalised words, optional hyphenated parts) in the signature
  section; three-word names are not supported yet (would swallow the next column in plain-text pages).
- `pesel`: not extracted (1 gold leaf in 41-60); emitting it needs a per-attorney association, left for later.
- Engine changes kept in the existing files (small diffs) to avoid conflicts with T006.

## Open issues
- Real documents: signatures in electronic form ("podpisano elektronicznie przez ..."), no dotted lines,
  or attorney signatures without a title would need extra strategies.
- `merge` attaches groups by order; a document listing signature groups in a different order than the members
  would mix them (could match by the name in the caption later).
