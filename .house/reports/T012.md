# T012: Profiles, parallel workers and an F1-vs-cost bench

- **Agent / model:** coder (Claude Sonnet 5.5)
- **Branch / commits:** task/T012-profiles-workers-bench (main merged in after "merge T013"; commit hash in the coordinator summary)
- **Date:** 2026-11-21

## Goal
Task `.house/tasks/T012-profiles-workers-bench.md`: profiles `text`/`ocr` (+ documented slot for `llm`), `--workers N`
with identical output, `python -m eval.bench` with gate and history, docs.

## What was done
- `odw2json/profiles.py` + `profiles/text.yaml`, `profiles/ocr.yaml`: selection `--profile` > `ODW2JSON_PROFILE` > `ocr`;
  strict validation (unknown key or unsupported `reader` kind = `profile error`, exit 2). `READERS` is the slot T016
  fills; an `llm.yaml` with `reader: {kind: llm, model: ...}` needs no pipeline change.
- `factory.ingestor_for(profile)` / `build_components(profile)`; `default_ingestor()` follows the active profile, so the
  web app (which calls `process_case`) is unchanged.
- `ingest/pdf.py`: `ocr.enabled: false` leaves pages without text empty (the document is then rejected = `{}`); env
  `ODW2JSON_OCR_CACHE=0` and `ODW2JSON_OCR_CACHE_DIR` (used by `bench --cold`).
- `pipeline.process_input(..., workers, profile, builder, stats)`: spawn `ProcessPoolExecutor` over PDFs, components built
  once per worker, results consumed in input order, files written only by the parent in sorted order. A failing document
  is `{}` + log (as before); a dead worker (tested with `os._exit`) fails only its own document, the rest is finished one
  document per fresh single-worker pool. Injected components force a serial run. `default_workers()` = env or
  `min(4, cpu_count // 2)`.
- onnxruntime threads: each pool worker gets `cores // workers` threads (`ODW2JSON_OCR_THREADS`, read by the RapidOCR
  backend); without it 4 workers x 8 threads oversubscribe the CPU.
- CLI: `--profile`, `--workers`, `--stats FILE` (per-document seconds). Docker compose passes `ODW2JSON_PROFILE` and
  `ODW2JSON_WORKERS`, the Dockerfile copies `profiles/`; `start.bat` already forwards CLI args.
- `eval/bench.py`: sets dev/heldout/skany/noisy/negatywne, one CLI subprocess per (profile, set, workers), peak RSS of
  the whole process tree via psutil (added to requirements.txt), exact + normalized F1 through `eval.score` as a library,
  reject accuracy, false rejects, p50/p95, docs/min, model size, JSON + markdown + `bench/history.csv`, `--gate`,
  `--accept`, `--cold`. Docs: `docs/PROFILES.md` (Polish, like the other docs), README and ARCHITECTURE updated.
- Tests (TDD): `tests/test_profiles.py`, `test_workers.py` (fake components, spawn pool, dead worker), `test_cli_profile.py`,
  `test_bench.py` (percentile, reject stats, score, set prep with a fake tree, table, history, gate, main with a fake
  measure), plus two ingest tests. None needs UZP data or OCR (one ingest test skips when the template scan is absent).

## Recommended default workers (16 GB i7)
4 (the shipped default `min(4, cpu_count // 2)` gives 4 on 8 threads). Throughput gain is 1.7x on cold scans and 1.3-3x on
digital sets (noisy), peak RSS 2.3 GB in the cold-OCR worst case, far under 8 GB. More than 4 would mostly add memory:
the machine has 8 hardware threads and onnxruntime already uses them.

## Tested and did not work
- First cold run with 4 workers and unrestricted onnxruntime threads: 3.6 docs/min vs 3.4 at 1 worker (no gain, p95 187 s,
  2.2 GB). Capping threads to `cores // workers` raised it to 4.5 docs/min vs 2.7 (the 1-worker figure was also slower in
  that run because of other load, so the exact ratio is noisy). Parallelism for OCR is only mediocre; a real cut in scan
  cost needs fewer OCR'd pages or a faster model, not more processes.
- A plain `ProcessPoolExecutor` aborts the whole run when a worker dies (`BrokenProcessPool`); fixed with the
  one-document-at-a-time retry.

## Next / open issues
- Cold scan cost is the real laptop risk: p50 6 s but p95 67 s per scanned document (multi-page). A page-level pool or
  skipping low-value pages would help; out of scope here.
- Timings are noisy when other jobs run; for a gate baseline run the bench on an idle machine and use `--accept`.
- `noisy` needs a tree from `eval.make_noisy` (`--noisy-dir`); not run here.
- `ODW2JSON_OCR_THREADS` is set with `setdefault` in the parent when workers > 1 (process-wide side effect).
