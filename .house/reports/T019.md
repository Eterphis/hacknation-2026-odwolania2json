# T019: Page image preprocessing before OCR

- **Agent / model:** coder (Sonnet)
- **Branch / commits:** task/T019-ocr-preprocess (3 commits: levels preprocessing, auto mode, banded second pass)
- **Date:** 2026-11-21

## Goal
Recover lines that OCR garbles on show-through / faint scans (misses-1.md rows 1-4, 18), ship the winner as default
if scan F1 does not drop and OCR cost stays within +40% (D-022). Task: tasks/T019-ocr-preprocess.md.

## What was done
- `odw2json/ingest/preprocess.py` (numpy + Pillow only, no new dependency): `levels` (gray, then levels stretch,
  black point 40 following the page ink up to 110, white point = black + 100), `needs_retry`, `shaky_bands`,
  `merge_lines`.
- `ingest.preprocess: none | levels | auto` (env `ODW2JSON_PREPROCESS` wins), default **auto**. Cache key includes the
  setting (`_CACHE_VERSION` 2). Text-layer pages are untouched (OCR path only).
- `auto`: OCR the page as before. If >= 5 lines have conf < 0.8, re-OCR only the horizontal bands around those
  lines after `levels`, and replace shaky baseline lines by cleaned lines that read better (never touching lines with
  conf >= 0.8; lines lost in pass 1 are added).
- Tests: tests/test_ingest_preprocess.py (levels, merge, bands, auto retry gate, cache key, env, default).
- docs/PROFILES.md updated. No new component, so EXTERNAL_COMPONENTS.md unchanged.

## Rows 1-4 and 18
- Rows 1-4 (odw 0005): OCR is recovered. Before: `nr referencyjny:` followed by `Z     e     ien` (conf 0.71) and
  `1a n z tf y:`. After: `ZP/12/2026, ogłoszenie o zamówieniu nr 2026/BZP 00879135/03 opublikowane w Biuletynie
  Zamówień` (0.98) and `1. postanowień Opisu Przedmiotu Zamówienia (OPZ). stanowiącego ...` (0.97), plus ~25 other
  garbled show-through lines on pages 2-5. Output: numer_bzp and numer_postepowania are now filled (2 of 4 leaves).
  czynnosc_powod_id and czynnosc_opis stay null: the text now contains the OPZ line, so that is a recipe
  matter (T018 area), not OCR.
- Row 18 (prz 0008, `opiata ... Maknowsiu`): NOT recovered. Tried: levels, Otsu, adaptive, higher dpi (150-400),
  line crop upscaled 1.5-3x raw and levels; best result is `Maknowsk`/`Maknowsku`, never `Malinowski`, and the `ł`
  is read as `i` throughout. It is a recognition limit of the mobile model on a low-res print, not show-through.

## Tested and did not work
- Always-on levels: fixes 0005 but loses diacritics and fragments lines elsewhere, scan F1 0.9639 -> 0.8546.
- Otsu: recovers some lines but breaks others (`Maknowalu`, `postppowansu`); adaptive mean: noise lines; plain
  contrast stretch / gamma 3: no recovery or garbage.
- Whole-image levels is fragile: black/white points of 40/140 recover the ZP line, 40/160, 60/120, 80/120 do not.
- Full-page second pass in auto: same F1, +73-79% time. Banded pass: same F1, +23%.
- Higher dpi only: no change in speed or text (detector resizes anyway); line upscaling: worse.
