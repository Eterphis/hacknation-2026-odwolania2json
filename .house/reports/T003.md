# T003: Ingest to word-box pages with per-page OCR fallback

- **Agent / model:** coder (Claude Sonnet 5.5)
- **Branch / commits:** task/T003-ingest-ocr (3 commits, worktree .worktrees/T003-ingest-ocr)
- **Date:** 2026-11-21

## Goal
`odw2json.ingest.default_ingestor(config)` turns any PDF into a `Document` of word-box `Page`s (text layer via
pdfplumber, OCR fallback per page). Task: `.house/tasks/T003-ingest-ocr.md`.

## What was done
- `odw2json/ingest/layout.py`: line clustering by y-overlap, blank line between blocks, hyphen joining only in `text`
  (never in `words`), `is_garbage_text` (too short, >5% broken chars / `(cid:N)`, <60% alphanumerics; rule and dotted
  lines like `-----` or `.....` are ignored in the ratio).
- `odw2json/ingest/ocr.py`: `OcrBackend` protocol `ocr(image) -> [(text, box, conf)]`, registry
  (`register_backend`), selection by env `ODW2JSON_OCR` > config `ocr.backend` > `rapidocr`. Backends: `rapidocr`
  (default) and `tesseract` (optional, pytesseract + binary + `pol`). To add one: implement `ocr`, call
  `register_backend("name", factory)`, set `ODW2JSON_OCR=name`.
- `odw2json/ingest/pdf.py`: `PdfIngestor`. Pages rendered by pypdfium2 (scale = min(200 dpi, 2400 px long side)),
  OCR lines split into words (box width shared by character count), pixels mapped to PDF points, clamped to the
  page. Lines under `ocr.min_conf` (0.6) are dropped (black redaction bars read as "n on nn"). Per-page OCR result
  cached by sha256(file)+page+dpi+min_conf+backend in `%TEMP%/odw2json-ocr-cache` (`ingest.cache`, `ingest.cache_dir`).
  stdout/stderr forced to UTF-8 on import.
- `requirements.txt` (appended): pypdfium2, rapidocr, onnxruntime, opencv-python-headless, numpy, Pillow.
- Tests: `tests/test_ingest_layout.py`, `tests/test_ingest_pdf.py` (20 tests, fake backend for the OCR path).

## OCR backend chosen and why
RapidOCR 3.10 (Apache-2.0) on onnxruntime, CPU. The wheel bundles PP-OCRv6 small det+rec models, so
`pip install -r requirements.txt` is enough: no model download, no system binary, no GPU (verified: first run offline
of the model files, nothing fetched). It reads Polish diacritics (ę ł ó ą ż ś ć ń seen correctly in the scan).
Tesseract `pol` stays an optional backend (needs the binary; Docker). The language-specific Latin model is reachable
via `ocr.rec_lang: latin` but is downloaded from modelscope at first use, so it is not the default. Licences: all
Apache-2.0/BSD/MIT (pypdfium2 Apache-2.0 or BSD-3; no PyMuPDF, no Ghostscript).
Caveat: opencv-python-headless must be 4.x here; the resolver's newest (5.1) wheel is 48 MB and slow on this network.

## Tested and did not work
- First garbage heuristic (letters/all chars >= 0.6) flagged 6 bank transfer confirmations (rows of `-----` and many
  digits) as garbage, which sent them to OCR and made the check run >25 min. Fixed by ignoring decoration characters;
  now 0 of 180 PDFs falls to OCR.
- Concurrent `pip install` runs (my own duplicates) stalled for 30+ min on the slow link; killed, re-run one at a time.
- Latin recognition model: not used, needs a runtime download.
