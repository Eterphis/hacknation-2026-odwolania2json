# T009 report: case-level consistency checks and repairs

Branch `task/T009-case-consistency` (cut from T014). Status: review.

## What was built
- `odw2json/case/` (generic: no class names; AC-3 grep also clean there): `paths.py` (path language `a.b[*].c`),
  `step.py` (`run_case`, `apply_case`, config loader). Configuration: `recipes/case.yaml`.
- Relation fields: `a`/`b` = {class, path}; `compare` digits|text|contains; `quantifier` a_in_b|b_in_a|any;
  `validator` + `repair`; `soft` (a miss = ok None "not mentioned", for titles that depend on payment kind).
  `contains` is fuzzy: folded diacritics/case, legal-form tokens (sp. z o.o., S.A., ...) ignored, ISO date matches
  d.m.Y / d-m-Y / d/m/Y. Checks are emitted only when both classes are present in the case; rejected documents
  (no extraction) are ignored; a single-document case (scans) yields no checks and no change.
- Repair: an identifier that fails its checksum validator or has evidence confidence < 0.6 is replaced by the other
  document's checksum-valid value if they differ in <= 2 positions that are OCR-confusable (groups `0O 1lI 5S 8B 08 56 38`)
  and there is exactly one candidate. Recorded as Evidence rule `case.repair`, snippet "repaired X -> Y from <relation>".
  A valid value is never replaced; if both fail the checksum nothing changes.
